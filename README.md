# Master Group — одностраничный сайт + закрытая статистика

В комплекте:
- `index.html` — публичная страница; счётчик не показывается посетителям.
- `admin.html` — отдельная панель администратора с входом.
- `firebase-config.js` — конфигурация Firebase (нужно заполнить).
- `firestore.rules` — правила, запрещающие посетителям читать статистику.
- `README.md` — инструкция.

## 1. Настроить Firebase

1. Откройте Firebase Console и выберите существующий проект.
2. В Project settings → General → Your apps откройте или создайте Web App.
3. Скопируйте конфигурацию в `firebase-config.js`, заменив все `PASTE_...`.
4. В Authentication → Sign-in method включите Email/Password.
5. В Authentication → Users создайте пользователя администратора с вашим email и паролем.
6. Откройте пользователя и скопируйте его UID.
7. UID администратора уже подставлен в `firestore.rules`.
8. В Firestore Database создайте базу данных, если её ещё нет.
9. В разделе Firestore → Rules вставьте содержимое `firestore.rules` и нажмите Publish.

Важно: не публикуйте пароль администратора. Firebase Web App config содержит клиентские идентификаторы, а не секрет администратора; доступ защищают Authentication и правила Firestore.

## 2. Опубликовать на GitHub Pages

Загрузите в корень того же репозитория все четыре файла:
- `index.html`
- `admin.html`
- `firebase-config.js`
- `firestore.rules` (это файл правил для копирования в консоль, не исполняется сайтом)

Если в репозитории уже есть сайт, скачайте/сохраните копию старых файлов перед заменой. Убедитесь, что GitHub Pages публикует нужную ветку и папку.

Публичная страница: `https://ВАШ-ЛОГИН.github.io/ВАШ-РЕПОЗИТОРИЙ/`
Панель администратора: `https://ВАШ-ЛОГИН.github.io/ВАШ-РЕПОЗИТОРИЙ/admin.html`

## 3. Как работает статистика

- Открытие страницы записывается как `page_view`.
- Нажатия записываются отдельно для WhatsApp, Telegram, Viber, Instagram и телефона.
- Пока реальные контакты не добавлены, нажатие показывает «Ещё в разработке».
- Статистика не выводится на публичной странице. Админ-панель требует вход.
- Посетители могут только создавать разрешённые события. Читать события может только UID администратора, указанный в правилах.
- Уникальные посетители оцениваются по случайному идентификатору браузера; это не точная идентификация человека.

## Ограничения и стоимость

Этот вариант использует Firebase напрямую из браузера и не требует собственного сервера. Использование Firestore/Auth может оставаться в бесплатных квотах при небольшом трафике, но бесплатность не гарантируется: квоты и условия Firebase меняются, а при росте посещаемости возможны расходы. Проверьте бюджет/лимиты в Firebase Console.

Для небольшого сайта админ-панель загружает до 5000 событий за выбранный период. При росте сайта статистику лучше агрегировать на сервере, чтобы избежать больших запросов.
